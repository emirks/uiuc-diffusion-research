# Feature store — colocated per-generation features (PROPOSAL, awaiting owner approval)

**Written:** 2026-09-17 · **Status:** APPROVED 2026-09-17 (owner, all six decisions in §11) · **SCOPE (owner, 2026-09-17): population `gridv3` only** — see `POPULATION_gridv3.md`; every other variant, the legacy caches and P6 are deferred · executing P0–P3, GPU (P4) gated on a separate go

## 0. One paragraph

Generations are in perfect shape (`store/gens`, 123 variants, 26,397 mp4s, contract v2). The features
that every metric is computed from are not: ~350k hash-named `.npz` files across 27 directories, keyed
by `sha1(path|mtime|size|model|short_side)`, so nobody can say what is cached without recomputing
hashes, and the paper's own features live in an August campaign folder (`misc/refvfx_baseline/probe/cache`).
This proposal moves every feature **next to the video it describes** — `videos/<item>.mp4` ↔
`features/<item>/<namespace>.npz` — under one pinned namespace registry, with a manifest per variant and
one CLI (`coverage · fsck · migrate · extract`). Migration for our paper arms and the corpus is a CPU-only
hard-link pass (probe: 60/60 hits on DINO, tracks, temporal LPIPS); the three externals need a ~3 GPU-h
re-extraction because they were scored before being registered into the store.

## 2. Principles (best practice, in priority order)

1. **Path is identity.** A feature file sits at the mirror of its video's path. Coverage is `ls`. No hashes in names.
2. **Files are the truth; manifests are an index.** Any manifest can be rebuilt from the files (`fsck --rebuild`). No lock files, no databases.
3. **Staleness by content.** Each feature records the video's sha256; `fsck` rehashes when size/mtime changed and flags mismatches. Moving the store changes nothing.
4. **One namespace = one pinned extractor.** Model id + revision + preprocessing + code sha, registered once in `store/FEATURES.md`. A pin change is a new namespace; old files are never overwritten.
5. **Cache backbones, derive heads at scoring.** Expensive network outputs are features (DINO CLS, CLIP, VideoPrism, tracks, RAFT magnitudes, temporal LPIPS). Cheap pairwise quantities (endpoint LPIPS vs a 9-frame clip, cosines, ECDF lookups) are computed at scoring and land in scores, not features.
6. **Self-describing files.** Every `.npz` carries a `_meta` JSON (video sha, host, code sha, created, origin) so a file found alone still explains itself.
7. **Atomic, restartable, shard-safe.** Write to `<file>.tmp-<pid>` then `rename`; shards own disjoint items; skip-if-exists; safe under `--requeue`.
8. **Machine is identity-bearing** (store rule; v4 does not reproduce eps↔DeltaAI at the 0.005 bar). `host` is recorded per file; `fsck` warns when one variant mixes hosts.
9. **Nothing numeric changes.** This is an I/O refactor. Acceptance = byte-identical migrated files + the harness's own bar-8 reproduction (warm rerun ≤1e-6, six cold anchors).

## 3. Layout

```
store/
  FEATURES.md                                  ← namespace registry (pins), like ARMS.md
  gens/<NNN_arm>/<KK_variant>__<machine>/
    meta.yaml                                  ← + features: {ns: {have: n, of: n_videos, hosts: [...]}}  (tracked)
    grid.jsonl
    videos/<item>__s<seed>.mp4
    videos/SHA256SUMS                          ← standard `sha256sum -c` file, one line per mp4 (tracked)
    features/
      manifest.jsonl                           ← one line per feature file (gitignored; rebuildable)
      <item>__s<seed>/
        dino_cls@dinov2b-r256.npz
        cotracker3@g20-m384-v2.npz
        lpips_t@alex-r256.npz
        clip_b32@r256.npz
        videoprism@f16r288.npz
        raft_mag@r256.npz
        clip_l14@r224.npz
  datasets/006_transitions_std121_v3/  (→ data/processed/transitions_std121)
    <class>/<clip>.mp4
    <class>/features/<clip>/<ns>.npz            ← same rule for corpus clips (references, pools)
    <class>/features/manifest.jsonl
eval_ladder/conds/
    <clip>_start9.mp4, <clip>_end9.mp4          ← 4,947 endpoint clips
    features/<clip>_start9/<ns>.npz             ← same rule
```

Rule, stated once: **`features/` is a sibling of the directory that holds the video; inside it, one folder per
video (the video's stem), one file per namespace.** Per-item folders (not per-namespace) because the loader
opens one folder per item and the human question is "what does this one have".

**Amended at P0 (2026-09-17):** meta is a JSON **sidecar** `<ns>.json` next to `<ns>.npz`, not inside the npz — so a migrated
feature can be a hard link of the legacy file (zero extra bytes; legacy caches are kept). The sidecar holds:
`{"ns","video":"<relative path>","video_sha256","video_size","video_mtime_ns","host","code_sha","created","origin":"extracted"|"migrated:<old path>"}`.
`manifest.jsonl` = the same records, one per line, plus `shape`/`dtype`.

Tags are frozen once written. `@` separates name and tag (not shell-special; safe on taiga, Slurm, Python, rsync).

## 5. Library and CLI

`src/diffusion/feature_store.py` (library, no CLI — repo rule):

```python
class FeatureStore:
    def path(self, video: Path, ns: str) -> Path         # the one rule from §3
    def has(self, video, ns) -> bool
    def get(self, video, ns) -> dict[str, np.ndarray]     # arrays (+ "_meta" parsed)
    def put(self, video, ns, arrays: dict, meta: dict)     # atomic tmp+rename; appends manifest line
    def coverage(self, video_dir: Path) -> dict[ns, Coverage]   # have/of/hosts per namespace
    def fsck(self, video_dir, rehash: bool=False) -> Report      # orphans, stale (sha mismatch), mixed hosts, manifest drift
    def rebuild_manifest(self, video_dir) -> int
```

`scripts/store_features.py` (CLI):

| command | does | GPU |
|---|---|---|
| `coverage [--gens GLOB] [--md]` | matrix variant × namespace → `have/of`; `--md` writes `store/FEATURES_COVERAGE.md` | no |
| `fsck [--rehash] [--rebuild-manifest]` | §2 checks; exit 1 on any stale/mixed-host | no |
| `sha256sums --gens GLOB` | writes `videos/SHA256SUMS` (skips unchanged by size+mtime) | no |
| `migrate --from DIR... --gens GLOB --corpus --conds [--dry-run]` | recompute legacy keys, **hard-link** hits into place, write `_meta`/manifest, report misses | no |
| `extract NS --gens GLOB [--shard i/n]` | fill misses only; loads the backbone once; atomic writes | yes |

Migration is a hard link, not a copy: `misc/`, `outputs/`, `store/` are one filesystem (verify `stat -c %d` in P1); the old file
becomes a second name for the same bytes, so the old caches can be deleted later without touching the new tree.
Legacy `.npz` are hard-linked as-is; the sidecar `.json` carries the meta (P0 amendment). The golden test asserts the link (same inode) and that the arrays load.

## 10. Risks and how they're handled

| risk | handling |
|---|---|
| hard links refused (different filesystem / permissions) | P1 checks `stat -c %d`; fallback = copy (48 GB, still CPU-only) |
| legacy file corrupt / truncated | `migrate` loads each hit before linking; failures are listed as misses |
| a video changed since its features were extracted | sha in `_meta`; `fsck --rehash` flags stale; `extract` refills |
| mixed-host features inside one variant | `fsck` warns; eval `meta.yaml` names the scoring host; the table builder refuses mixed hosts unless `--allow-mixed-hosts` |
| concurrent shards append the manifest | manifest is rebuilt from files after every job (`fsck --rebuild-manifest`); files are the truth |
| certification status of the harness | I/O-only 4.0.1 + bar-8 reproduction; nothing numeric touched; diff reviewed against `versioning.INSTRUMENT_PATHS` |
| externals' old features unrecoverable | re-extract (~3 GPU-h); their evals/030 scores stay valid — features are inputs, not outputs |
